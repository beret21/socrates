Socrates — Know Your Self

A session & settings manager for Claude Code · Design Document · 2026-06-10

1Problem

Hard to get back to a session

After a reboot (OS update, etc.) it is hard to find the CLI session you were working in.

claude --resume <UUID> works, but there is no way to manage UUIDs.

Hard to see what is configured

Settings are scattered across ~/.claude/ and per-project .claude/,

and the growing fleet of subagents/skills from harness engineering has no single view.

2Approach (agreed)

AreaDecision
Inside Claude/socrates slash command assigns an alias to the current session
Terminalstandalone socrates (short alias soc) + optional claude soc ... zsh wrapper
Picking a sessionfzf TUI selection → copies --resume <UUID> to the clipboard (no auto-launch — compose flags like --dangerously-skip-permissions yourself)
Status viewsterminal summary socrates map + static HTML dashboard socrates report
Stackpicker: shell + fzf + jq · analysis/HTML: Python stdlib only

3Ground truth (official docs + local verification)

  • Session storage: ~/.claude/projects/<encoded path>/<UUID>.jsonl — lines carry sessionId, cwd, timestamp, gitBranch, slug
  • Session ID: ${CLAUDE_SESSION_ID} substitution inside SKILL.md — docs/skills
  • Resume: claude --resume "<id>" — docs/cli-reference
  • Project metadata: projects key in ~/.claude.json — lastSessionId, cost, model usage
  • No collisions: no existing user commands → /socrates and socrates are free
  • Caveat: custom flags like claude --soc are unsupported → zsh wrapper routes claude soc ...

4Architecture

┌─ Inside a Claude session ──────────┐    ┌─ Terminal ────────────────────────┐
│  /socrates <alias>                 │    │  socrates list   (fzf picker)     │
│  └─ records ${CLAUDE_SESSION_ID}   │    │  socrates name   (set alias)      │
│     + cwd                          │    │  socrates map    (status, TTY)    │
│                                    │    │  socrates report (HTML dashboard) │
└──────────────┬─────────────────────┘    └──────┬────────────────────────────┘
               │ write                           │ read/write
               ▼                                 ▼
        ~/.claude/socrates/sessions.json  ← alias registry (the ONLY write target)
               ▲                                 │ read-only
               │                                 ▼
   ~/.claude/projects/*/*.jsonl   ~/.claude/settings.json    ~/.claude.json
   (session transcripts)          (+ hierarchy of .claude/)  (project metadata)

5Command spec

/socrates inside Claude

UsageBehavior
/socrates <alias> · /socrates name <alias>record an alias for the current session UUID
/socrates · /socrates statusshow current session ID, alias, project, registry count
/socrates helpusage guidance (reserved — never registered as an alias)

socrates terminal

CommandBehavior
socrates / socrates listfzf list: ★ aliased sessions on top + ~50 recent.
Enter → copies --resume <UUID> · Ctrl-Y → UUID only
socrates name [alias]pick a session, set/update its alias
socrates mapsettings hierarchy, hooks, plugins, MCP, skills/agents as an ANSI tree
socrates reportgenerate ~/.claude/socrates/report.html and open it
socrates versionprint the plugin version

zsh wrapper

claude() {
  if [[ "$1" == "soc" ]]; then shift; soc "$@"; else command claude "$@"; fi
}

HTML report sections

  • ① Projects × sessions table (aliases highlighted, copy buttons for --resume UUID)
  • ② Settings hierarchy tree (global → parent folders → project)
  • ③ Harness inventory: agents / skills / plugins / MCP servers
  • ④ Cost & model-usage summary

6Safety principles

Read-only transcripts

jsonl files under ~/.claude/projects/ are never modified. Writes go only under ~/.claude/socrates/.

~/.zshrc untouched

Never edited automatically — the wrapper snippet is printed for the user.

Large-file safe

Only the head/tail of session jsonl files is parsed.

8Decision log — 2026-06-10

  • One name: canonical name socrates everywhere; terminal short alias soc. Proper noun → minimal collision risk with future built-ins.
  • Distribution: the repo is its own plugin marketplace (/plugin marketplace add beret21/socrates → /plugin install socrates@beret21); a SessionStart hook links the CLI into ~/.local/bin, so no split install. install.sh remains as a secondary path.
  • White-background HTML: all HTML artifacts use a light theme.
  • Security cleanup: published history rewritten to one clean commit; placeholder UUIDs/paths in docs; local-only folders excluded via .gitignore.
  • English everywhere: commits, docs, comments, CLI output in English; README.ko.md is the Korean secondary README.
